# How Far Are We from the Ideal Large Model? MiniMax M3 Review

## I. Introduction

Let me ask everyone a question: what should the ideal large model look like for ordinary users?

In my view, if you're going to use a large model daily, it should ideally meet four conditions simultaneously.

(1) **Strong performance**, especially powerful programming capabilities.

(2) **Large context window**, ideally reaching 1 million tokens — reasons explained later.

(3) **Multimodal**, handling not just text but also images, video, audio, etc., and ideally capable of computer operation.

(4) **Affordable**, with generous quotas at a low price.

Is there an ideal model that meets all these conditions?

Unfortunately, as far as I know, there isn't. Foreign flagship models meet the first three conditions, but are too expensive. Domestic open-source models are affordable, but often single-modal — unable to fully handle text, images, video, and audio simultaneously — and their context windows are small.

## II. MiniMax M3

This Monday, MiniMax released their latest [flagship model M3](https://www.minimaxi.com/models/text/m3).

I didn't pay much attention at first, thinking it was just a routine version update. But after glancing at the [release report](https://www.minimaxi.com/blog/minimax-m3), I was suddenly shocked to discover that **it meets all four conditions simultaneously**.

Compared to the previous version M2.7, the context window has been expanded from 200K to 1M, the single-modal text model has been upgraded to multimodal, and benchmark scores haven't dropped. As for pricing, there's a matching Token Plan.

It looks like a perfect candidate for the ideal large model.

This piqued my interest, and I immediately ran some simple tests.

## III. 1M Context Window

Before we begin, let me explain the benefits of a larger context window.

**The context window is the maximum number of tokens a model can process at once.** The larger this value, the more background information can be provided to the model in a single pass, and theoretically, the more accurate the generated results.

For large projects and long-range operations, every interaction with the model carries all previous operation results from the start. Clearly, a large context window is crucial — no worries about running out of space.

The common context window size is 200K tokens. Why not make it larger?

The reason is that more tokens mean more computation. Each token needs to calculate its relationship with every other token, and as the context window grows, computation increases dramatically, affecting model performance and cost.

MiniMax M3's context window is 1M tokens — the largest accessible to ordinary users.

It can achieve this by using a new technical approach: the sparse attention architecture MSA. This scheme chunks and filters tokens, selecting representative tokens for computation, avoiding full computation. According to the [official introduction](https://www.minimaxi.com/blog/minimax-m3), with the same number of tokens, the computation is only "1/20 of the previous generation."

> "With a 1M context, M3's per-token computation is only 1/20 of the previous generation. In the prefilling stage, we achieved over 9x acceleration, and in the decoding stage, over 15x acceleration advantage. Moreover, in multiple controlled experiments, MSA's capabilities are largely on par with full attention."

This means that even though the context window has increased 5x, the computation has actually decreased, without affecting generation quality ("largely on par with full attention").

## VI. MiniMax Code and Token Plan

Finally, besides the large model itself, a desktop client was also released: [MiniMax Code](https://agent.minimaxi.com/download).

![](https://cdn.beekka.com/blogimg/asset/202606/bg2026060315.webp)

It is comparable to Claude Code and Codex, primarily for programming.

![](https://cdn.beekka.com/blogimg/asset/202606/bg2026060316.webp)

It's built on the open-source projects OpenCode and Pi Agent, optimized for M3 — the official recommendation is to use them together.

Besides programming, this desktop client also has Computer Use capability, allowing connection to a phone for operating the computer from the phone.

The official example: you can say to your phone, "Help me open the local ERP client and batch enter invoice information from this Excel file." The desktop client follows the command. Since I was mainly testing the large model, I didn't test this desktop client, but I think it has enormous potential.

This desktop and web client also have a [Token Plan](https://www.minimaxi.com/) with usage-based pricing.

![](https://cdn.beekka.com/blogimg/asset/202606/bg2026060317.webp)

The plan has changed compared to before. According to the [official announcement](https://platform.minimaxi.com/docs/token-plan/migration), due to M3's increased token consumption, the plan has switched from per-use to per-token billing, with added weekly limits. The cheapest plan is 49 yuan per month for 600 million tokens — sufficient for most personal use. Even so, it still offers great value compared to other token plans.

Previously, Token Plans without weekly limits are now being resold at high prices on secondary platforms — a testament to their popularity.

![](https://cdn.beekka.com/blogimg/asset/202606/bg2026060406.webp)

## VII. Conclusion

After initial testing, my impression of MiniMax M3 is very positive. Since the upgrade from M2.5 to M2.7 wasn't dramatic, my expectations weren't high, but testing showed that **M3's upgrade is very noticeable** — significantly better than M2.7 in every aspect.

Combined with its expanded 1M token context window and native multimodal support, I think this model is worth recommending. No other domestic open-source model seems to achieve all these simultaneously.

Overall, **MiniMax M3 is a well-balanced model with no weak points**, meeting the conditions for an ideal large model: strong performance, broad applicability, affordable price, suitable for daily use, and also suitable for agents like OpenClaw.

This was just a brief test — I'll continue testing further and encourage you to try this model too, exploring its performance in complex scenarios together.
